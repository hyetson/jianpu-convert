# 民乐乐团：乐器能力、独立声部与和音

核查日期：2026-10-23。本文用于后续语义和排版封装。机器可读表为 `configs/instrument-capabilities.json`，当前录入 18 类配置。能力分类只是处理提示，不能据此删除源音高、合并独立声部或生成原谱没有的声部。

## 分类依据

必须分别记录三个层级：

1. **事件内多音**：一个节奏事件里有多个音高，例如笙的和音、琵琶和弦、筝的撮。它仍属于一个声部。
2. **单个演奏者的独立声部**：旋律与伴奏有各自的时值、休止、连线；例如筝或扬琴的复调，笙的旋律与和弦伴奏。每个声部内部还可以有和音。
3. **乐团独立分组**：不同演奏者或组别承担 I、II 等分部。即使乐器通常每人只奏单音，乐团中也可有多声部。

“单人多音”和“乐团多声部”不是互斥分类；同样，单个演奏者的独立声部也不能全部压成一个和弦。MusicXML 的 [voice](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/voice/) 本身就允许包含音符、和弦和休止，是本项目嵌套模型的直接依据。

乐团人数也不等于声部数：六名乐师可以齐奏同一条旋律；一名乐师也可能处理两个独立层次。香港中乐团[编制/音域表](https://www.hkco.org/uploads/docs/682542db204771.pdf)给出人数，[早期谱表模板](https://www.hkco.org/uploads/docs/563ac23705a6a1.pdf)还列有笛、笙、唢呐的 I/II 和二胡 I/II。它们证明这些编制确实存在，不代表任何作品都必须分成两行。

## 按乐器整理的处理矩阵

以下“保留”是本项目规则。“可分组”表示原谱有独立分部时必须保留，不是判定每首作品都需要分部。

| 乐器 | 单个演奏者的同声部多音 | 单个演奏者的独立层次 | 乐团中的独立声部需求 | 转换建议 |
| --- | --- | --- | --- | --- |
| 梆笛、曲笛、新笛/大笛 | 常规演奏以单音为主；特殊复音另核 | 常规不作为默认假设 | I/II 有编制资料；依原谱启用 | 默认单行，真实分部时上下对齐；不把两名演奏者的音合为单人和弦 |
| 箫、洞箫 | 常规以单音为主 | 非默认，特殊写法另核 | 可按作品配置多人/分部 | 保留源声部，分类不构成复音禁令 |
| 各音区唢呐 | 常规以单音为主；特殊复音另核 | 非默认 | 高/中音 I/II 有资料；不同音区也可能是独立乐器部 | 音区品种、演奏者分组、音乐声部分别记录 |
| 各音区管子 | 常规以单音为主 | 非默认 | 原谱决定是否分组 | 不能因为采用大谱表就断定有两条音乐声部 |
| 传统笙 | 和音明确存在，受具体型号限制 | 复调可能性保留，需核对管列与指法 | 独奏/合奏和分组按原谱 | 禁止限定为“只画和弦”；也不能保证任何音群均可奏 |
| 现代键笙及高/中/次中/低音笙 | 和音是重要能力 | 有和弦与对位/旋律伴奏资料 | 笙 I/II 及不同音区分部有资料 | 允许独立声部内再含和弦；具体型号不能混为一种指法系统 |
| 高胡、中胡 | 通常单线旋律；不预设普通和弦能力 | 特殊写法保留，逐件核实 | 乐团弦乐分组依原谱 | 家族参考只作保守提示，不把二胡技法无条件移用 |
| 二胡 | 普通和弦不作为默认；特殊双音须核实 | 弓奏与左手拨弦可并存，需明确源证据 | 二胡 I/II 有直接资料；divisi 按原谱 | 分组、单人特殊复合技法、泛音音高角色保持分离 |
| 琵琶 | 双弹/双挑、扫拂、和弦及琶音有依据 | 如旋律、低音有独立事件流则保留；不是每个扫弦都属复调 | 多人独立琵琶声部有重奏实例 | 一个事件里的和弦共享节奏；独立流分别保留；两者允许共存 |
| 柳琴 | 双音、和弦、扫弦、琶音有教材依据 | 独立流按作品保留，单人对位可奏性另核 | 分部按乐团原谱 | 不把轮奏/扫弦本身当作第二声部 |
| 中阮 | 双音、三和弦、分解和弦有教材依据 | 独立层次按源流保留，可奏性另核 | 多人独立阮声部有重奏实例 | 和弦、分解和弦与独立声部是不同结构 |
| 大阮 | 保留阮族多音能力；具体组合需核 | 原谱有则保留，逐件核实 | 作品决定是否分组 | 此项是阮族层级推断，不照搬中阮定弦/指法 |
| 三弦 | 本轮已查资料不足以给出完整多音技法表，标记 unknown | 复杂写法保留，待原谱/专门教材核实 | 可按作品分组 | 不因“有三条弦”推定任意和弦可奏，也不删除已写出的音群 |
| 古筝 | 撮、和音、双手琶音明确存在 | 教材明确包含复调练习 | 筝重奏/分组由作品决定 | 双手与演奏者数量分开；一名演奏者的两层音乐里还可各含和音 |
| 扬琴 | 和音、琶音明确存在 | 乐团复调支撑与双手独立层次需保留 | 扬琴重奏有直接实例 | 分类为 struck-string；不能把所有双手材料压成一个同步和弦 |

吹管组的“通常单音”是正常奏法层面的保守归纳，不是排除特殊复音。新笛和大笛也只是共用织体提示，并非认定它们结构相同。

## 核心证据与适用范围

- **笙**：Samuel Wong Shengmiao《QI》笙章的和音/复调段明确讨论和弦与对位，也强调不同笙型不能直接互换作品。用于支持“和弦与独立声部可并存”，不据此设置固定和弦音数上限。[作者原章，Atlas Ensemble 托管](https://www.atlasensemble.nl/assets/files/instruments/Sheng/Sheng%20by%20Samuel%20Wong%20Shengmiao.pdf)，印刷页 138、141-142。
- **筝**：教材同时包含撮、双手琶音、和音及复调练习，直接说明不能仅按“单人乐器”归成一条节奏线。[音乐事务处古筝教材](https://www.lcsd.gov.hk/en/mo/common/doc/faq/faq_01_syb_0206.pdf)，I-1、A-2。
- **扬琴**：乐团教育资料介绍其和弦、琶音与复调作用。[NACYO 扬琴介绍](https://www.nacyo.org/instruments/yangqin)。乐团将扬琴编入广义弹拨组，并不改变它以击弦发音的事实。[香港中乐团弹拨乐器介绍](https://www.hkco.org/en/Instrument-Rd/Chinese-Instruments/Plucked-String-Instruments.html)。
- **琵琶**：原章记录单人多弦发音、扫拂及琶音动作，支持事件内多音；不能凭一个扫弦符号推导两条旋律。[《QI》琵琶章](https://www.atlasensemble.nl/assets/files/instruments/Pipa/Pipa%20by%20Samuel%20Wong%20Shengmiao.pdf)，印刷页 25-26。
- **柳琴、中阮**：教材分别列出双音、和弦和琶音训练。[柳琴教材](https://www.lcsd.gov.hk/en/mo/common/doc/faq/faq_01_syb_0201.pdf)，I-1、A-1；[中阮教材](https://www.lcsd.gov.hk/en/mo/common/doc/faq/faq_01_syb_0204.pdf)，I-2、I-3、A-2。大阮的细节不能仅凭中阮教材直接确定。
- **胡琴边界**：VICO 对二胡双音持谨慎态度，但也介绍弓奏与左手拨弦的并行使用。因此“通常单线旋律”不等于永久禁止独立层次。[VICO 二胡写作资料](https://vi-co.org/resources-study/instrument-corner/erhu/)，Bowing and Fingering / Pizzicati。高胡、中胡的相应细节仍须分别核实。
- **多人独立弹拨声部**：琵琶四重奏、阮四重奏、扬琴二重奏有乐团节目实例。它们说明可存在独立演奏者关系，不能证明任意管弦作品的某小节必然 divisi。[香港中乐团节目](https://www.hkco.org/en/Concerts/Plucked-String-Notes-1.html)。

以上为公开可读文献，不因此获得教材图形的开源再分发授权；项目只保存链接和概括。开源的 MusicXML、SMuFL、Bravura 仍按[既有技法参考](CHINESE_INSTRUMENT_TECHNIQUES.md)分别承担语义、字形、字体职责。

## 后续数据模型应保留的层级

```text
乐器种类/具体型号
  → 乐团乐器部 part
    → 演奏者或分组 performerUnit（可未知）
      → 逻辑声部 logicalVoice（可跨谱表）
        → 节奏事件 event
          → pitches[]：一个或多个音高
          → marks[]：琶音、扫弦、震音等技法
```

必须保留以下组合，而不是设置互斥的 `single / chord / polyphonic` 乐器类型：

| 组合 | 例子/含义 | 输出原则 |
| --- | --- | --- |
| 一流、单音事件 | 笛子普通旋律 | 单行 |
| 一流、多音事件 | 笙和音、琵琶和弦 | 一个声部内竖排，按源节奏处理 |
| 多流、各流单音 | 曲笛 I/II、胡琴 divisi | 独立行头、同拍对齐 |
| 多流、各流可有多音 | 笙旋律与和弦伴奏、筝复调、两名琵琶各奏和弦 | 每行内部继续支持多音及各自琶音，不压扁，也不拆成“每音一行” |

`performerUnit` 和 `logicalVoice` 是后续封装建议，尚未全部接入渲染器。当前的 `staff:voice` 只是保留下来的源事件流标识，不能证明演奏者人数，也不能保证跨谱表的同一逻辑声部已经归一。I/II 目前是显示顺序；后续应通过显式映射区分乐团分部、同一演奏者的左右手、旋律/伴奏等标签。

## MusicXML 判别和当前限制

1. 优先保留 `<voice>`、`<staff>`、`<chord/>` 和原谱说明，不凭乐器名称或音头数量推断分部。
2. `<arpeggiate>` 是和弦奏法标记；已经写成有时值的分解和弦音列仍保留这些时值，不自动压成一个多音事件。来源：[chord](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/chord/)、[arpeggiate](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/arpeggiate/)。
3. 同时出现且时值相同的两个源声部也不自动合并。反过来，同一谱表或同一音符组上的所有音也不必然属于一个逻辑声部。
4. MusicXML 允许和弦成员具有较短时值；**当前导入器仅完整合并等时值和弦**，不等时值成员会报告问题。后续应增加音高成员时值，而不是强行改拍或默认改成两名演奏者。
5. 本目录没有乐器的 `maxVoices` 或 `maxChordNotes` 硬限制，不代表已经实现任意多声部。现有 `single` 入口仍要求一个源事件流，`dual` 仍要求最多两个；更多流应进入后续专门方案，不能静默丢弃。
6. 同时和音、泛音触点/实音、装饰音与特殊复音须按源角色区分；证据不足时保留并待校对。

## 已接入的配置与审计

单/双声部自定义 profile 可指定顶层 `instrumentProfileId`，由入口传入 part；底层配置可直接指定 `parts[].instrumentProfileId`。显式 ID 与 `instrumentFamily` 冲突时在 OMR 前报错；缺省或 unknown 家族可从显式 ID 补齐。不会按中文名称自动套用型号。

例如，复制现有双声部配置并保留它的字体和排版字段，指定：

```json
{
  "instrumentProfileId": "sheng-keyed",
  "localVoices": {"primaryVoice":"1:1"}
}
```

这只补充能力信息，不会因为“笙能和音”而将两个声部合并。若具体型号并未确认，应先不选择该 ID。

目录的三个能力字段互相独立：`pitchCollections`、`soloIndependentVoices`、`ensembleIndependentParts`。`common`/`documented` 有直接材料支撑；`extended-review`/`score-dependent-review`/`unknown` 表示应保留并继续核实。`basis` 和 `sources` 标明家族推断及证据出处，不把可行性保留写成普遍可奏性结论。

运行的 `score.json` 在 part 下保存 `instrumentProfile`（如已明确选择）和 `textureSummary`。后者记录：

- 多个源事件流、含多音的事件、含琶音标记的事件；
- 主音事件按记谱时值是否有跨流重叠；
- 重叠时是否还包含多音事件，即 `hasConcurrentVoicesAndChordEvents`；
- 每流的多音和琶音归属；`voiceMeaning` 保持 `unresolved`，不自动猜测演奏者分工。

它区分“某处有和弦、另一处有第二声部”与“同一时段的多声部里还有和弦”。这是源语义审计，不是声学延音分析或自动换行策略。

## 验证与扩展范围

本轮构建包含 79 项 Node 和 49 项 Python 测试。新增覆盖两个并行声部各自含不同音数的和弦及各自琶音、同拍对齐、能力非互斥、实际并发审计、profile 冲突与未知证据保留。合成回归不等于真实 PDF 的识别精度或具体和弦的演奏可行性。

运行 `python scripts/verify-instrument-textures.py` 可验证完整的“显式笙配置 → MusicXML → 源流/和音审计 → 双行渲染”链路。它使用 3 音和弦与 2 音和音分别占据两个独立流，并各带独立琶音；结果保存在 `tmp/instrument-textures/verification.json`，不把两个流推断为两名演奏者，也不声称这个人工例子适合任意型号的笙。

革胡/低音革胡、大提琴/低音提琴、古琴、箜篌/竖琴，以及有固定音高的打击乐应另建具体配置。本轮不把它们强行归入单音或单声部类别；例如打击乐多条节奏层不一定是普通音高和弦，无固定音高的记谱更不应套成音级数字。现有管弦乐表提供了扩展入口，具体技法与记谱需继续按乐器核验。
