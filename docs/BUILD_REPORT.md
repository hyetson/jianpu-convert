# 首轮构建与端到端试验

日期：2026-10-14。结论：本地项目可构建，三份真实五线谱 PDF 已经过 Audiveris、MusicXML 解析和 PDFKit 导出；音乐内容尚未通过校验，生成结果是诊断初稿，不能作为排练分谱。

## 已完成

- 经用户分别批准后安装项目 Python/Node 依赖、Audiveris 5.11.0，下载 Bravura 字体及英文 OCR 数据。
- TypeScript 构建与 16 项音乐语义/证据修正测试通过。
- 三乐器配置、Audiveris 命令行适配、MusicXML 原始时值/声部解析、首调简谱转换、矢量 PDF 排版及诊断报告已实现。
- 输入与参考 PDF 禁止覆盖；输出只写 output/jianpu。测试代码没有从参考简谱抄录音符。
- 合成回归样例为 24 小节、三个声部、174 个非休止事件，生成两页；它明确标记为合成数据。

## 真实输入结果

输入是 example 目录中梆笛、曲笛、新笛 G 的三份原始五线谱。初次原始 OMR 的休止计数出现明显误识别，如 14→4、25→2；本轮用 PDF 数字文字层和 OMR 休止符坐标修正了 23 处计数，修正证据和原始识别均保留。

最终诊断初稿：`output/jianpu/丝绸之路_竹笛分谱_试转换.pdf`，32 页。当前版逐乐器/独立声部排版，不具备参考简谱中成熟的同音声部压缩与版式密度。

转换数据中有 1255 个非休止事件；这只是识别结果数量，不代表与输入的真实音符数量一致。三份乐谱的不同小节数量、重复编号及错误时值仍然存在。

| 校验类型 | 数量 |
| --- | ---: |
| 小节时值与拍号不符 | 84 |
| 声部中未编码的时间缺口 | 7 |
| 重复小节编号 | 3 |
| 某乐器缺失对齐小节 | 14 |
| 乐器之间拍号/小节长度不一致 | 40 |
| 合计 | 148 |

另有 8 项排版/连线复核提示。以上是程序校验项数量，不能等同于真实乐谱的错误音符数量，也不能据此计算识别准确率。PDF 用红框标出能定位到小节的错误，缺失小节显示占位提示，不自动编造休止或音符。

本轮试验显示，Audiveris 对这些特殊布局和自由节奏片段的识别仍有障碍；它也会生成不同的声部和不一致的计时结构。PDFKit 导出问题与 OMR 语义问题已区分：所有 32 页均通过非空、矢量输出和字体嵌入检查，并生成逐页 PNG/缩略图供检查，但音乐内容仍未通过。

默认严格导出已实测：发现 148 项错误后阻止生成 PDF。只有显式 `--draft` 才导出带“校对初稿”标记的诊断文件。

## 下一步实现重点

优先解决源 PDF 的谱行/小节边界与真实编号映射，再处理自由节奏、连音和不同声部的时值。数字生成 PDF 的原生文字/几何可作为校正证据；不能用任意填充、删音或改拍号消除错误。待 MusicXML 与原谱一致后，再压缩同音声部并优化总页数。

不把本次构建成功误写成识谱准确性已达标。首轮端到端工程路径已验证，正式排练可用的转换结果尚需后续识别/校正工作。
